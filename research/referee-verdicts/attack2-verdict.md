`paper/proof3-verdict.md`. Every load-bearing lemma was re-derived by hand; every finite

## Bottom line — the question the task asks

> **Yes. Open Problem 1 of Moradi–Rampersad–Shallit is genuinely answered.** The family
> `h_m = t_{2,m} = (s_2(i) mod m)` is generated by a minimal `m`-state msd DFAO and has
> `sc(h_m(ni)) >= (1/2) n m^2` for *every* odd `n >= 3` and every `m >= 2`. Lemma A and
> Lemma B are both correct — I re-derived both and found no gap — and the third ingredient
> (the factor complexity of `t_{2,m}`) is correctly quoted from the literature and
> independently brute-forced here. No error was found in Theorem A, in its constants, or in
> Theorem C.

Qualifications, none of them fatal:

* The answer is an **assembly of three existing pieces**, not a new hard theorem: the paper's
  own Theorem 16 proof generalises verbatim (that is Lemma A); the paper's Lemma 15 needs a
  replacement, supplied by a two-line construction plus Gelfond 1968 (Lemma B); and the
  `m^2 n` growth is already in Tromp–Shallit 1995 / Starosta 2012. What was missing in the
  source is exactly the join. The document says so in its ledger; the headline
  "**Verdict: solved**" is nevertheless accurate.
* `C = 1/2` is **exactly attained** at `(m,n) = (2,3)` (`sc = 6 = (1/2)*3*4`), so `1/2` is
  the largest constant valid for all odd `n >= 3` in this family. The document does not
  claim otherwise; worth stating, since the `limsup` claim (`1 - 1/(3m)`) is about a
  subsequence only.
* Four defects, all cosmetic or in §5 (the non-load-bearing part). See §6.

## 1. The primary source

I did not take the quotation on trust. `arXiv:2512.10017` has five versions (v1 2025-12-10 …

From the v5 PDF, verbatim:

> We do not know if the bounds in Corollary 10 are tight. This seems worthy of further
> study, so we state it as an open problem.
>
> **Open Problem 1.** Find a class of automatic sequences `(h_m(i))_{i>=0}`, generated by a
> DFAO of `m` states with msd-first input, such that there is a constant `C` so the linear
> subsequences `(h_m(ni))_{i>=0}` have at least the state complexity `C n m^2` for

Identical to `ATTACK-2.md` §1, word for word. Theorem 9(a) (window automaton,
`delta'([r_0..r_{n-1}],a) = [s_0..s_{n-1}]`, `s_d = delta(r_j,b)`, `j = floor((na+d)/k)`,
`b = (na+d) mod k`), Corollary 10(a) (`<= knm^2`), Theorem 1 (`rho_x(n) <= kn rho_{M̂}(2) <=

12] with `i=0`), Theorem 16 and Corollary 17 (Brlek) are all as the document describes.
`ATTACK-2.md`'s summary of each is accurate.

**Still open?** Yes, and I can push the date past what the document checked.

* Semantic Scholar lists exactly **one** citing paper: *State Complexity of Shifts of the

* arXiv:2603.21645 (*Fibonacci-automatic*, Mar 2026) does not touch it, as the document says.
* **New evidence the document did not have:** Delaram Moradi's MMath thesis, *State

## 2. Lemma A — re-derived, correct

Hypothesis used: `h(k^L X + y) = h(X) + h(y) (mod m)` for `0 <= y < k^L` (for a weighted
digit sum this forces `w_0 = 0`; both families in the document satisfy it).

Forward direction: for `|z| = L`, `n[xz] = k^L n[x] + n[z]`; with `n[z] = k^L g + w`,
`g = floor(n[z]/k^L) <= n-1` because `n[z] < n k^L`; so `h(n[xz]) = W(x)[g] + h(w)`, which
depends on `x` only through `W(x)`. Correct.

Converse: `L` with `k^L >= n`; `Z -> floor(nZ/k^L)` starts at `0`, ends at `n-1`
(`floor(n(k^L-1)/k^L) = n-1` exactly when `n <= k^L`) and has steps `<= ceil(n/k^L) = 1`, so
it is onto `{0,...,n-1}`. Correct. Both halves check out, for every `n`, even or odd, and the
state set is indexed by *values* `[x]` (the output depends on the value only), so
`sc = #{W(j) : j >= 0}`. **PROVED.**

Machine check (mine, `paper/verdict-attack2/`):

* `ref_sc.sc_nerode` — a **theory-free** msd Myhill–Nerode BFS: state of `X` is the raw
  table `(u(k^L X + j))_{L<=Lmax, j<k^L}` computed from the oracle `u(i) = popcount(n i) mod m`
  alone, transitions `X -> kX+d`, plus a replay of the resulting DFAO against `u` for
  `i < 20000`. Distinct signatures are *provably* distinct states, so it cannot over-count.
* `ref_sc.sc_windows` — my own implementation of the window automaton.
* `lemAB.py` — `#{W(j) : j < J}` counted straight from `popcount`, no automaton at all.

All three agree in every cell tried, including even `n` where Lemma A still applies and
`sc < rho`: e.g. `m=7, n=6`: `#W(j) = sc = 91 = sc(h(3i))` while `rho(6) = 231`.

## 3. Lemma B — re-derived, correct

Fix `2^t >= n`, `P = 2^t a + b`. For `0 <= g < n`: if `b+g < 2^t` then `h(P+g) = h(a)+h(b+g)`,
else `b+g-2^t < 2^t` and `h(P+g) = h(a+1)+h(b+g-2^t)`. So the factor is a function of
`(h(a), h(a+1), b)`. Correct (and I stress-tested exactly this parametrisation on 400 random
DFAOs, `k<=5`, `m<=5`: 0 violations).

`n` odd `=>` invertible mod `2^t`; `n j_0 = 2^t a_0 + b` with `j_0 in [0,2^t)`, and
`j = j_0 + 2^t j'` gives high part `a_0 + n j'`, i.e. every `a' >= a_0` with `a' = a_0 (mod n)`.
Take `T in {1..m}`, `T = u-v+1 (mod m)`, `L > T`, `a' = 2^L A + 2^T - 1`: bits `0..T-1` are 1,
bit `T` is 0, so `s(a') = s(A)+T` and `s(a'+1) = s(A)+1` (the `+1` cannot carry into `A`
because `2^T < 2^L`). With `h(A) = v-1` this gives `(h(a'),h(a'+1)) = (v-1+T, v) = (u,v)`.
The side condition `2^L A = a_0 - 2^T + 1 (mod n)` is one congruence `A = A_0 (mod n)` since
`2` is invertible mod odd `n`. Gelfond 1968 (base `q`, `gcd(m,q-1) = 1`; for `q = 2` this is
`gcd(m,1) = 1`, always true) gives infinitely many such `A`. Every step checks out. **PROVED.**

Machine check. `sc = rho` is what Lemma B buys, and my independent `sc` equals my
independently brute-forced `rho` in all 300 cells (`m=2..7`, odd `n <= 101`). Separately,
`lemB_big.py` counts windows at multiples of `n` directly from `popcount` for `j < 2*10^7`
and recovers `rho` exactly in the slowest-converging cells:
`(m,n) = (7,15) -> 644`, `(7,23) -> 1022`, `(7,31) -> 1372`, `(6,43) -> 1416`, `(7,35) -> 1554`,
`(7,101) -> 4648` (`j < 8*10^6`). (Short prefixes undershoot — at `j < 1.3*10^5` the `(7,31)`
count is only 1315 — which is why the document's "empirical Lemma B" table should be read as
convergence-limited, not as evidence of failure.)

## 4. The factor complexity input — quotation and formula both correct

Starosta, arXiv:1104.2476 = Kybernetika **48** (2012) 361–370, Table 2, with `q` = least
positive integer with `q(b-1) = 0 (mod m)` (so `q = m` when `b = 2`), aperiodic case
`b != 1 (mod m)`:

```
n = b^k + 1 + l,          0 <= l < b^k - b^(k-1):        C(n) = qm(n-1) - m(b^k - b^(k-1))
n = (2b-1)b^(k-1) + 1 + l, 0 <= l < b^(k+1)-2b^k+b^(k-1): C(n) = qm(n-1) - m(b^k - b^(k-1) + l)
```

`ATTACK-2.md` quotes this correctly, including both ranges. Reduction to `b = 2`: row 1 is
`r = l < 2^(k-1)` (plus `l = 0`, which is `p = k-1, r = 2^(k-1)`), row 2 is
`r = 2^(k-1) + l >= 2^(k-1)`; in both `m^2(n-1) - m*max(2^(p-1), r)` with `n-1 = 2^p + r`,
`0 < r <= 2^p`. Correct. Tromp–Shallit, IPL **54** (1995) 313–316, is indeed the
`y(i) = s_2(i) mod k` case (confirmed from the paper's abstract and Starosta's [13]).

Independent brute force (`rho.py`, exact suffix-doubling ids on a `2^22` prefix, no hashing,
convergence-controlled against a `2^20` prefix): `rho` matches the closed form for **`m = 2..7`
and every `n` from 3 to 130** — `0` mismatches, `0` non-converged. The `m = 2` case reproduces
Brlek. So the citation is not load-bearing inside the tested range.

## 5. Theorem A and its constants

*Statement.* `sc(t_{2,m}(ni)) = m^2(n-1) - m*max(2^(p-1), r)`, `n-1 = 2^p + r`, `0 < r <= 2^p`.

Arithmetic, re-derived: `2^(p-1) <= (n-1)/2` and `r <= (n-1)/2` (equality at `r = 2^p`), so
`sc >= (1 - 1/(2m)) m^2(n-1) >= (3/4) m^2 (n-1) >= (1/2) n m^2` for `n >= 3`. Correct, and the
last step is exactly why `n >= 3` is needed. `min_r max(2^(p-1), r)/(n-1) = 1/3` at
`r = 2^(p-1)`, i.e. `n = 3*2^(p-1)+1` (odd for `p >= 2`), giving
`limsup sc/(n m^2) = 1 - 1/(3m) >= 5/6`. Correct.

## 6. Defects found

1. **§5(i) is overstated.** "In every cell the maximiser is a group automaton (a weighted
   digit sum ...); no random DFAO ever won." Exhausting *all* zero-consistent identity-coded
   3-state base-3 DFAOs at `n = 7` (`exhaustive.py`): the maximum `54 = m^2(n-1)` is attained
   by **42** automata, of which only **18** are group automata; e.g.
   `delta = [[0,0,1],[1,0,2],[2,2,0]]` attains 54 and is not a group automaton
   (`delta(.,1)` is not a permutation). The defensible statement is "*a* group automaton
   always attains the maximum", which is what the data supports (and the document's own §5
   already notes a non-group 4-DFAO tying 312).
2. **Zero-consistency is never stated.** Theorem 9(a) — and hence Theorem C and the whole
   `#windows` construction — needs `delta(q_0,0) = q_0`; otherwise `h'(0) != q_0` and the
   induction `h'(k i + b) = delta(h'(i), b)` fails at `i = 0`. I found this the hard way: on
   random DFAOs *without* that constraint my two general implementations disagree wildly
   (e.g. `k=2, m=3, n=11`: 35 vs 12), and with it they agree. Nothing in the document breaks
   (both families are zero-consistent, `w_0 = 0`), but "exhaustively over *all* 2- and
   3-state DFAOs" (§5) should read "all zero-consistent ones" — the others do not generate a
   sequence in the msd-with-padding convention the rest of the document uses.
3. **`2^(p-1)` is a half-integer at `p = 0`.** For `n = 3`, `n-1 = 1 = 2^0 + ...` forces
   `p = 0`, and the formula only gives the right answer (`2m^2 - m`) because
   `max(1/2, 1) = 1`. Write the `n = 3` case separately or restrict to `p >= 1`. Cosmetic —
   the value is right (checked: `m=2..20`, `n=3`).
4. **§2's engine methodology rests on an unproved claim.** "For these families every level
   set `{i : h(ni) = a}` needs the full `sc` states" is asserted, not proved; it is what
   licenses reading the per-letter `dfa T[n*i]=a` state count as the DFAO size. It held in
   all 14 engine cells I ran (every letter gives the same count, equal to `sc`), so the
   engine numbers stand, but it is an empirical bridge, not a proof.

Two non-defects I checked and could not break: the claim that the coding may be taken to be
the identity when maximising (correct — the Nerode classes of the intrinsic sequence refine
those of any coding, so `sc(h(ni)) <= sc(h'(ni))`), and the `k=4` refutation of
`sc <= m^2(n-1)` (reproduced: weights `(0,0,1,0)` mod 3 at `n = 31` gives **312** > 270, as
does the random DFAO `[[0,2,0,0],[1,1,0,1],[2,1,2,2]]`; both under Theorem C's 372 — note
372 comes from the `rho_{M̂}(2)(n-1) + m(k^t-n+1)` form, the looser `m((k-1)n+1)` form gives
552, so the document's "372" is consistent but uses the first expression).

## 7. Theorem C

Re-derived. `P = k^t a + b`, `0 <= b < k^t`, `t` minimal with `k^t >= n`; every position in
`[P, P+n)` is `k^t(a+e) + r`, `e in {0,1}`, and `h'(k^t A + r) = delta(h'(A), (r)_k)` (msd
concatenation, given zero-consistency). Hence the factor is determined by `(h'(a),h'(a+1),b)`,
and by `(h'(a),b)` alone when `b + n <= k^t`; there are `k^t-n+1` of the latter `b` and `n-1`
of the former, giving `rho_{h'}(n) <= rho_{M̂}(2)(n-1) + m(k^t-n+1)`, and `k^t <= kn-1` gives
the stated `m^2(n-1) + m((k-1)n+1)`. Correct at `n = 1` (`<= m`) and at `n = k^t`. **PROVED.**

Machine check: 400 random zero-consistent DFAOs (`k <= 5`, `m <= 5`, 8 values of `n`,
prefixes of `4*10^5`): **0** violations of the `(h'(a),h'(a+1),b)` parametrisation, **0** of
the `(h'(a),b)` parametrisation, **0** of the counting bound.

Novelty assessment: this is the one-shot version of the standard blocking argument behind
[AS, Thm 10.3.1]; it is a real improvement on `k n m^2` for `m >> k`, but I would not call it
more than folklore-grade. The document labels it a "sharpening of Corollary 10(a)", which is
fair.

## 8. Observation B (base 3)

Reproduced independently with both of my constructions: `h_m(i) = (#2s in (i)_3) mod m` gives
`sc = m^2(n-1)` **exactly** for `m = 2..6` and every tested `n` with `3 ∤ n`
(`n = 2,4,5,7,8,11,13,16,22,31,40,44`), and `sc(h(ni)) = sc(h(n'i))` for `n = 3^v n'`
(`m = 2,3,5`, `n <= 21`). Lemma A does apply verbatim (the sequence is 3-digit-additive with
weights `(0,0,1)`, `w_0 = 0`). The two missing ingredients are correctly identified as open
in the document: the `rho = m^2(n-1)` formula, and a Lemma-B analogue (Gelfond's hypothesis
`gcd(m,q-1) = 1` fails for base 3 and even `m` — though, as the document notes, the relevant
sequence is a weighted digit sum, not `s_3`). **MACHINE-VERIFIED, not proved** — exactly as
claimed.

## 9. What is actually new here

* **New and correct:** Lemma A (as a general statement; the `k=m=2` case is the source's
  Theorem 16, with the same proof), Lemma B (the `m`-general replacement for the source's
  Lemma 15, via Gelfond), Theorem A and hence **the answer to Open Problem 1**, Theorem C
  (mild).
* **Not new:** the `rho_{t_{2,m}}` formula (Tromp–Shallit 1995; Starosta 2012), Gelfond's
  theorem, Theorem 9/Corollary 10/Theorem 16.
* **Not established:** Observation B's two ingredients; the exact maximum over `m`-state
  `k`-DFAOs for `k >= 4`; the `c > 0` case. All three are listed as open in the document's
  ledger — the ledger is honest.
