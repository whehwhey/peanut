# ARCHITECTURE

Peanut's engine is a small Rust crate (`engine/`, package name `automatheus`,
binary `peanut`, edition 2024, no external dependencies — `engine/Cargo.toml` has
an empty `[dependencies]`). Six modules:

```
engine/src/
  main.rs        stdin command loop / dispatch (docs/COMMANDS.md)
  dfao.rs        DFA-with-output: sequence generated by a k-uniform morphism + coding
  dfa.rs         DFA/NFA core: product, projection, determinization ladder, minimize
  base.rs        primitive Presburger automata: adder, less_than, equal, constant, power_of_k
  logic.rs       lexer, parser, AST, compiler (formula -> Dfa)
  learn.rs       guess-and-verify construction of FE (docs/LEARNFE.md)
  membudget.rs   global allocator with a hard live-byte budget (docs/GUARD.md)
  export.rs      `export` command: automaton -> flat JSON, for the GUI (docs/COMMANDS.md)
  progress.rs    `AM_PROGRESS=1` structured stderr event stream (docs/COMMANDS.md)
  compat.rs      Walnut-compatibility mode: run Walnut command scripts unchanged (docs/WALNUT-COMPAT.md)
  transducer.rs  finite-state transducers and Dekking-style transduction (docs/BREADTH.md)
  negbase.rs     negative-base numeration systems, `msd_neg_k` (docs/BREADTH.md)
  ostrowski.rs   Ostrowski numeration systems from a quadratic irrational (docs/BREADTH.md)
```

## Data flow

```
def NAME k m start w0..w_{m-1} coding
        |
        v
  Dfao::from_morphism            (dfao.rs)   -- the automatic sequence T
        |
formula text  --lex/parse-->  Ast            (logic.rs)
        |
        v
  Compiler::compile(&Ast)  ->  Dfa            (logic.rs, using base.rs primitives
        |                                       and Dfao::pred_letter/pred_eq)
        v
  ? / witness / enum / dfa / finite            (main.rs, reads the resulting Dfa)
```

`let`/`learnfe` additionally register `(params, Dfa)` in `Defs` (a
`HashMap<String, (Vec<String>, Dfa)>`), making the automaton callable as
`$NAME(...)` from later formulas — `Ast::Call` binds each argument through a fresh
existentially-quantified variable and inlines the stored `Dfa` (renamed to the
fresh names) via `Dfa::and` + `Dfa::exists`.

## DFAO: the sequence

`Dfao::from_morphism` builds the standard automaton for a k-uniform morphism: `m`
states (one per letter of the morphism alphabet), transition `t(s, d) = w_s[d]`,
output via `coding`. `Dfao::at(n)` evaluates `T[n]` by reading `n`'s base-k digits
(msd or lsd per the active `dfa::is_lsd()` flag) from the start state.
`Dfao::pred_letter(x, a)` / `pred_eq(x, y)` build the primitive one/two-variable
automata `T[x]=a` and `T[x]=T[y]` that `logic.rs` conjoins into larger formulas —
this is where the sequence enters the logic at all; every other automaton in the
system is pure Presburger arithmetic over `<N, +, <, V_k>`.

## Logic compilation

`logic.rs` is a straightforward recursive-descent compiler: `Ast::Cmp` and the two
`Ast::SeqLetter`/`Ast::SeqSeq` variants bottom out in `base.rs`/`Dfao` primitives;
`And`/`Or`/`Not`/`Imp`/`Iff` are automaton `product`/`complement`; `Exists`/`Forall`
are `Dfa::exists` (`Forall` is `complement().exists(v).complement()`, i.e. De
Morgan — there is no separate universal-projection algorithm). Every operator
returns a **minimal, trimmed** `Dfa`, so intermediate blowup can only ever come
from the two operations that build new states: `product` (bounded, `|A|*|B|`) and
`exists` (subset construction, unbounded in principle — this is the whole subject
of `docs/TARGET1.md`).

Linear arithmetic terms (`Lin`, a constant plus a sorted map of variable
coefficients) are compiled by `Compiler::lin_auto`/`add_auto`/`cmp_auto` into
chains of `base::adder` automata, folding summands directly rather than building a
zero automaton and adding one term at a time, to avoid needlessly multiplying the
working alphabet (each extra fresh variable multiplies alphabet size by `k`).

## Digit orders

Global flag (`dfa::set_lsd`/`is_lsd`), not per-automaton. It changes three things:
- `Dfao::at` reads digits msd-first or lsd-first.
- `Dfa::zero_closure` — after every `exists`, the automaton must be re-closed under
  the padding convention. msd padding is *leading* zeros, so closure needs a real
  subset construction (states reachable by prepending zeros get merged into their
  target's acceptance). lsd padding is *trailing* zeros, so closure only rewrites
  the accepting set (`accept[q] |= accept[t(q,0)]`, fixpoint) — no determinization
  at all. This asymmetry is why lsd is sometimes dramatically cheaper for the same
  formula (`docs/TARGET1.md` Finding 1: 45/47 msd memory-budget failures on the
  random sweep finish in lsd with modest size).
- `enum`/`dfa`'s word encoding in `main.rs` places each tuple's digit at the msd or
  lsd end of the shared word.

`mode msd|lsd` is the only command that touches this flag; it applies to every
automaton built afterward, including already-`def`'d sequences (mixing modes
within one sequence's automata is meaningful and is how the msd/lsd comparison
rows in `docs/TARGET1.md`/`docs/LEARNFE.md` are produced).

## The determinization ladder

`Dfa::exists` builds an NFA by dropping one track from the alphabet (union over
the k old symbols that project to each new symbol) and must determinize it. Naive
forward (Rabin–Scott) subset construction is what blows up (Khodier's Open Problem
1 aspect B). The ladder, in `Dfa::exists` (`dfa.rs`, comment dated 2026-08-16):

```
1. forward subset construction, capped at AM_CAP0 (default 50,000) subsets
2. Brzozowski (reverse, determinize, reverse, determinize), capped at
   max(AM_CAP0 * 4, 200,000) subsets each side
3. forward subset construction, capped at AM_CAP (default 3,000,000)
4. Brzozowski, capped at max(AM_CAP * 4, 8,000,000) each side -- panics
   ("forward and reverse determinization both blew up") if this also fails
```

Every stage that succeeds is followed by `zero_closure().minimize()`. The
motivating measurement (`docs/TARGET1.md`, "Construction (aspect B)"): a *small*
forward cap that fails fast into Brzozowski beats a large forward cap by orders of
magnitude — e.g. an exact-count-3 predicate: 482 states in 0.0 s via the ladder vs.
6 GB exhausted by a straight 3M-subset forward attempt. `AM_DEBUG2=1` traces which
branch fires and the state counts at each step.

`Dfa::reverse_determinize` (subset-construct the reversed NFA, i.e. Brzozowski's
first half alone) is also used directly by `Dfa::forall`'s complement-based path
and is available as a building block outside `exists`.

## Minimization

`Dfa::minimize` (`dfa.rs`) is textbook: trim to states reachable from the start
state via BFS renumbering, then Moore partition refinement to merge Nerode-
equivalent states. Run after every operation that can introduce redundant states
(product, determinization, zero-closure) — automata are kept minimal throughout
compilation, not just at the end, so a mid-formula state count in an `AM_DEBUG`
trace is a true lower bound on that subformula's language.

## The learner (aspect B, take two)

`learn.rs` sidesteps the ladder entirely for the one predicate that motivated it
(`FE`): instead of compiling `A t. t<l => T[i+t]=T[j+t]` (which forces the subset
construction the ladder is built to survive but still costs real time/memory), it
learns the automaton by Kearns–Vazirani active learning against a cheap LCP oracle
and verifies the result with a two-sentence recurrence check that only ever
compiles *open* formulas (no `forall`, no subset construction at verification
time beyond ordinary product automata). Full design and proof: `docs/LEARNFE.md`.

## Guard layers

Three independent layers, engine / Python runner / system daemon, all detailed in
`docs/GUARD.md`: the allocator budget (`membudget.rs`, `AM_MEM_MB`) is the
innermost and is what actually stops a single process; `explore/engine.py` is
admission control plus a watchdog around child processes; `explore/memguard.sh` is
a system-level LaunchAgent backstop that kills any `peanut`/`automatheus` process
regardless of how it was launched. None of `dfa.rs`/`logic.rs`/`learn.rs` know
about any of this — they just allocate, and the allocator enforces the ceiling.
